# AsiBackbone EditorConfig Baseline

**Last reviewed:** 2026-11-15 ([AsiBackbone/.github#49](https://github.com/AsiBackbone/.github/issues/49))

The four AsiBackbone .NET repositories enforce code style in the build: each sets `AnalysisLevel` to
`latest-recommended`, `EnforceCodeStyleInBuild`, and `TreatWarningsAsErrors`. They share one set of formatting and
analyzer rules so that the same code is judged the same way in every repository.

## Where the reference copy lives

The reference copy of the shared rules is the
[NetCoreApplicationTemplate `.editorconfig`](https://github.com/AsiBackbone/NetCoreApplicationTemplate/blob/main/.editorconfig).
It is also the file NCAT emits into every generated application, so ReferenceApplication receives it through its NCAT
baseline refresh.

Every repository's `.editorconfig` has the same two parts:

1. **Shared rules.** Everything above the repository's extensions banner. This part is identical in every repository,
   except that NCAT's header adds one line saying its copy is also emitted into generated applications.
2. **Repository-specific extensions.** Everything below a banner of this form:

   ```text
   ########################################
   # <Repository>-specific extensions
   ########################################
   ```

   Extensions must target paths or conventions that exist only in that repository, and each must carry a comment that
   explains it.

To change a shared rule, change it in NCAT first, then copy the identical shared part into AsiBackbone and Learning.
ReferenceApplication picks it up at its next NCAT baseline refresh.

## Repository-specific extensions

As of the review date, the shared parts are identical, and every difference between the files is a labeled extension:

| Repository | Extension | Status |
| --- | --- | --- |
| AsiBackbone | Private fields use unprefixed `camelCase`; constants and `static readonly` fields use `PascalCase`; the shared `_camelCase` rule is turned off. | Intentional. AsiBackbone predates the shared convention, and renaming its private symbols has no API or behavior benefit ([AsiBackbone/AsiBackbone#768](https://github.com/AsiBackbone/AsiBackbone/pull/768)). |
| AsiBackbone | `nuget.config` uses two-space indentation. | Intentional. It matches the repository's XML style. |
| Learning | All text files use LF line endings. | Intentional. It keeps samples consistent across documentation tooling and non-Windows learning environments. |
| Learning | Twelve additional `suggestion`-level style preferences, such as primary constructors and simplified interpolation. | Intentional. They keep canonical teaching examples idiomatic. At `suggestion` severity they never fail a build. |
| Learning | `samples/**` relaxations for CA1050, CA1707, CA1859, CA1848, and CA1873, scoped to the sample paths that need them. | Intentional. Single-file samples and scenario-named tests trade library conventions for readability. |
| Learning | `**/bin/**` and `**/obj/**` treated as generated code. | Intentional. Sample builds produce intermediate C# under those folders. |
| NetCoreApplicationTemplate and ReferenceApplication | EF Core `**/Data/Migrations/*.cs` treated as generated code, with CA1861, IDE0005, and IDE0161 off. | Intentional. Migrations are generated by EF Core, and the rules apply to generated applications too. |

`.github` and `asibackbone.github.io` contain no C# and share a separate 16-line `.editorconfig` for text formatting
only. It isn't part of this baseline.

## Drift check

[`scripts/Test-EditorConfigBaseline.ps1`](scripts/Test-EditorConfigBaseline.ps1) reads each repository's
`.editorconfig` from its `main` branch and fails if the shared part differs from NCAT's, or if a file has no
extensions banner. It reads public files only. The
[EditorConfig baseline validation](.github/workflows/editorconfig-baseline-validation.yml) workflow runs it every week
and on pull requests that change it. The required *Validate organization profile* check runs its offline
`-SelfTest`.

```powershell
./scripts/Test-EditorConfigBaseline.ps1
./scripts/Test-EditorConfigBaseline.ps1 -SelfTest
```
